## 5. Architecture and Data Flow
Original source bytes → retained image/annotation identities → frozen whole-image split → preparation run / derived tile manifest → benchmark → bounded training → validation-selected candidate → locked test predictions and metrics → evaluation replay and separate training recreation → exact inference Lab release → Modal hosted image invocation.
Every edge is stored using explicit dataset, run, artifact, revision, release and deployment references. Readable workflow summaries extend existing Experiment/Run/Lab screens. Public evidence uses access-filtered links and selected summaries; it never automatically shares upstream private images or credentials.

## 7. Input, Output, and Error Contracts
One stored JPEG/PNG reference, ownership checked at submission and execution, max 20 MiB and 25 million pixels. Verify file bytes, decode safely, reject unsupported/corrupt/oversized data and path escapes. Input/model/config identities accompany every result. Coordinates refer to original image pixels; count is an integer, unit colonies, equal to the number of post-merge detections. Scores are detector scores, not calibrated count confidence. Return count, boxes/scores, annotated image, runtime, warnings and evidence links through existing outputs/artifacts. Failed inference never returns a default plausible count.
Hosted specs gain an additive stored-image type with explicit required-input semantics and bounded authenticated staging. Existing scalar/text defaults and immutable schema-1 digests retain their behavior. Per-invocation private scratch is deleted on every outcome.

## 8. Model Method and Uncertainty
Start with one colony class, YOLOX-Tiny depth/width from pinned upstream, image tiling at 640 pixels and 20% inference overlap. Tune confidence/merge settings using validation plates only; record raw and tiled comparisons. Random seeds, optimizer, augmentations, epoch count, hardware and exact dependencies are captured. The short benchmark determines batch size and affordable epoch budget. Candidate selection minimizes validation whole-plate count error while inspecting precision/recall and severe errors. Freeze the selected candidate/settings before final test access. Do not promise approved accuracy before training.
No calibrated whole-count interval is claimed. Human-readable errors and supported-domain caveats accompany results. Touching/merged colonies and acquisition shifts are explicit limitations. Baseline comparisons and difficult-image failures remain visible.

## 12. Verification and Test Design
Dataset tests cover duplicates/groups across splits, parent membership, corrupt identity, incomplete files, retention, and cross-account/team-role rejection. Recorder tests execute subprocesses and retain failures/timeouts, changed inputs and missing outputs. Training metrics derive from actual predictions. Native-versus-adapter inference must return identical counts/boxes under the same checkpoint/settings. Frozen test reports MAE, signed bias, WAPE ≤10%, p95 symmetric error ≤20%, precision/recall ≥90% each at IoU0.5, failures and density strata. Replay reproduces exact counts/aggregate metrics in the pinned environment. Training recreation executes independently and has WAPE within two percentage points of the selected model, both passing gates.
Product verification covers actual upload→hosted execution→annotated result→artifact retrieval, cross-account rejection, cold/warm start, queue/cancel/retry, pause/resume, failed deployment recovery, historical/scalar Labs, Chat routing/nonmatches, authorized replay from another workspace/account, and one verified production invocation. Isolated tests do not establish deployment readiness. Preserve exact commits/environments and cleanup evidence.
