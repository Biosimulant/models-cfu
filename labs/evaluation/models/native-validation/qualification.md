# Final-test identity lock

`src/lock.py` is a pre-outcome software guard, not an executed detector, a final-test runner, or a scientific acceptance report. No candidate has been locked yet.

After actual validation completes, retain its comparison JSON and predictions ZIP as native Files through Biosimulant MCP. Read back their original completed Run/revision and exact artifact byte identities. Verify the learned-weight File and its training origin separately. Never treat a fixture report as managed evidence. The future managed lock worker must use `freeze_from_artifacts` with those exact Files, the pinned original frozen split, and the complete, reviewed final-test adapter code/manifest identities.

The guard checks artifact byte lengths and SHA-256 values before decoding, requires exactly the 32 prespecified regular JSON ZIP members, and bounds both compressed and decompressed input. It recomputes every validation candidate's metrics from retained whole-plate detections with the approved metric algorithm. All 37 validation plates must complete under every candidate configuration, match their frozen groups, and produce unchanged recorded metrics. The selected candidate must match the prespecified ranking and pass every approved validation gate. These checks establish lock eligibility only; they do not establish final-test accuracy.

The returned lock binds the selected retained weights, one confidence/merge configuration, both validation artifact File identities and their Run/revision, the full validation-plan digest, exact original data/source pins, preprocessing, dependency environment, training recipe, the future test code and model manifest, all 37 test-original File identities, unchanged metric thresholds/bootstrap parameters, and zero test exclusions. No test annotation outcomes are accepted or inspected by this guard. The frozen split includes identity and partition metadata only. Metric, source-verification, and input-path algorithms must retain their reviewed validation byte identities.

Retain the canonical lock digest and native lock artifact before any final-test execution. The future test worker must call `verify` before reading test annotations, using the expected digest bound to its immutable Run plan. It must execute only the locked configuration; the validation candidate grid cannot be searched on the test fold. Source annotations, including edge-crossing and zero-area references, remain unchanged. All planned plates and explicit failures must be retained.

Saved-model replay must be a separate fresh managed inference Run using the same lock, weights, source, code, dependency environment and original images. Existing `metrics.replay_check` compares actual retained counts and aggregate metrics after both execution reports are independently verified. Training recreation must start independently from the same frozen training inputs, seed and recipe, with no selected checkpoint or weights as inputs, and keep its own managed history and training provenance. Its actual test evaluation must use the locked postprocessing configuration and unchanged gates; the two-percentage-point WAPE tolerance remains fixed. Mathematical comparison alone cannot establish either managed execution or independent training lineage.

The final-test adapter, managed lock execution, native replay, recreation evaluation, and hosted serving verification remain pending. This hand-authored guard requires manual scientific review and does not authorize public release. Local fixture checks are software evidence only. All account-backed scientific actions remain on Biosimulant MCP; no new production service deployment is part of this change.
