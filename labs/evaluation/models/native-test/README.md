# Locked original-image evaluation

This finite component is authored for managed Biosimulant execution on Modal CUDA. It is not active in the training graph and has not executed detector inference. No test outcomes have been read during authoring or software verification.

Before primary evaluation, obtain a passing validation-only result and retain a pre-outcome lock produced by the reviewed guard. The lock must bind the exact learned weights, reviewed component code/model manifest, validation-plan identity, frozen data/source/environment/preprocessing, chosen confidence/merge configuration, all37 original test Files and unchanged approved metrics. Read back the actual completed validation Run and native File origins; software cannot certify those account-backed relationships.

Supply exact native File references for source archives/inspection receipts, frozen split, original COCO annotations, learned EMA weights, retained lock and37 lexically ordered test originals. The public parameters bind the weight and lock byte lengths/SHA-256 values and the lock's canonical digest. `primary` rejects a prior test baseline. `replay` and `recreation` require the retained primary prediction JSON and its exact byte pins. Empty authoring defaults never authorize execution.

The fresh worker verifies code/data identity and the pre-test lock before reading any test annotation value. It uses the same native YOLOX-Tiny state-dictionary loading, exact-source SAHI, measured dependency/CUDA environment, original EXIF coordinate frame, letterbox preprocessing, batch8 inference and reviewed score/merge algorithms as validation. It executes the single locked mode and configuration; it does not search the validation grid on test data. Prediction candidates have minimum cached score0.05 and a20000-per-plate bound with explicit failure rather than truncation. All original reference boxes, zero-area counts and source edge crossings remain unchanged. Every test plate, detection and failure is retained. Work/command deadlines remain bounded, and each output is capped at64MiB.

`primary` retains actual whole-plate predictions and recalculates all approved metrics. `replay` requires the exact locked weight bytes, unchanged baseline references, dependency environment, code and settings; it compares actual counts/aggregate metrics and separately records exact detection parity. `recreation` may evaluate separately trained weights from the same pinned contract/recipe/pool, with the same fixed postprocessing and metrics. It compares both models' gates and the approved two-percentage-point WAPE tolerance. This evaluator does not establish independent training lineage: separately recorded fresh training inputs/history and native Run/File origin verification remain mandatory. It cannot substitute reuse of the selected checkpoint for independent recreation.

Receipt and retained report always leave `scientific_acceptance_established` false. A passing test metric report alone does not satisfy replay, recreation, intended-use review or exact public-release approval. Hand-authored coordinate, orchestration and analysis logic requires manual review. Actual managed source/API compatibility, accuracy, inference/replay, independent recreation and hosted/staging/authorized-user verification remain pending. No production service deployment or provider change is included.
